What runs where?

The GX10 serves the self-hosted Ornith and Qwen models for TechLabs AI. The Proxmox virtual servers in Nuday Data Centre run the website and the services behind projects such as Firewall Monitor and WiFi Doctor.

It keeps the models and project data on infrastructure we control — the lab AI server and our hosted Proxmox VMs — avoids per-token cloud pricing for the AI, and lets us tune the stack end to end.

SYS-01 // Architecture specification

Vinylfo Record Collection Manager

v0.16.13 · Stable
  • Go
  • Twitch OAuth / Twitch API
  • YouTube API
  • OBS WebSocket / OBS Overlay
  • SSE
  • Windows · macOS · Linux

Project Overview

Vinylfo is a self-hosted desktop application designed for streamers and audiophiles to manage their physical vinyl records while streaming metadata and media feeds to platforms like Twitch, YouTube, and OBS, alongside Stream Deck integrations.

Core Systems Architecture

  • Discogs OAuth & Sync: Import vinyl libraries and artwork through standard OAuth connections, running syncs asynchronously in database workers.
  • Multi-Source Duration Consensus: Queries MusicBrainz, Wikipedia, and YouTube APIs to resolve track durations, applying filters for closest match consensus.
  • OBS Server-Sent Events (SSE): Broadcasts low-latency "Now Playing", Album Cover, and Visualizer feeds on a local HTTP port directly into OBS browser sources.
  • Twitch Live HUD & Chatbot: Connects via device code OAuth to read chat events, moderate, launch viewer polls, and send announcements when record tracks advance.

SYS-02 // Architecture specification

Firewall Monitor & Firewall-Collector

server v0.11.233 collector v1.3.44
  • Go
  • SNMP v2c/v3
  • Syslog
  • sFlow
  • HTTPS / mTLS Relays
  • Docker

Project Overview

Firewall Monitor is a vendor-agnostic, lightweight Network Management System (NMS) focused on firewall fleets. It supports centralized deployments or distributed remote collection probes (Firewall-Collector) across multiple client sites.

Core Systems Architecture

  • Distributed SNMP Relays: The Firewall-Collector probe runs locally, polling edge firewalls from major vendors over SNMP v2c/v3 and batching telemetry to HQ over HTTPS/mTLS.
  • Syslog & sFlow Receivers: High-performance UDP parsing pipelines normalized to handle hundreds of events per second with rate-limiting filters.
  • Normalized Configuration Tracking: Periodically polls configurations via SSH/TFTP, normalizes values across different vendors, and stores differential code revisions.
  • Custom State Alerts: Evaluates data lag, traffic spikes, and interface metrics, sending notifications via Webhooks, SMTP Email, and IRC Bots.

SYS-03 // Architecture specification

SignArtSaver — Rust Server Gameplay Plugin

v0.11.14
  • C#
  • .NET
  • Oxide / uMod API
  • JSON Configs
  • Rust Survival Server

Project Overview

A native plugin developed for Rust survival game servers, attaching to Oxide/uMod engine hooks to implement client-side interactive economy boards, administrative alerts, and real-time performance metrics.

Core Systems Architecture

  • Low-Overhead Event Hooks: Attaches directly to player interaction hooks (gathering, trading, combat) without introducing stutter to the game thread.
  • In-Memory Database Sync: Maintains real-time player telemetry and points balances in memory, periodically saving checkpoints to disk using structured JSON configurations.
  • Admin Command Registry: Exposes chat and console commands with permission layers for server managers to issue adjustments, check logs, and run server diagnostics.
  • UI Overlay Renderer: Crafts custom vector and text screens using the Rust Game UI Engine, displaying data directly on player viewports dynamically.

SYS-04 // Architecture specification

WiFi Doctor — Room-by-Room WiFi Survey Fleet

Early access · US & Canada first
  • Go
  • Postgres
  • ClickHouse
  • NATS
  • Kotlin Multiplatform
  • React
  • Android · Android TV · Windows · macOS · Linux

Project Overview

WiFi Doctor finds and fixes weak WiFi, room by room. It turns the phones, Android TV boxes and computers you already have into a WiFi survey fleet, maps signal on your real floor plans, and tells you what to fix, room by room. Sensors are apps, not hardware: Android phones and tablets, Android TV boxes, Windows, macOS and Linux, including Raspberry Pi. No survey kit to buy.

Core Systems Architecture

  • Measured, not guessed: Heatmaps come from real scans on your floor plan; where nothing was measured, the map stays blank. A predictive view is always labelled as predicted.
  • Two ways to measure: Stationary sensors left in place scan about every 30 seconds, around the clock; guided walk surveys on an Android phone tell you which room to visit next and take a reading in each one.
  • Tells you what to change: Findings for weak coverage, crowded channels, roaming trouble and access-point spacing, each with the evidence behind it.
  • Reports and alerts: Survey reports as PDF and CSV with map and heatmap images; scheduled reports such as a weekly coverage PDF; alerts once sensors keep watching.
  • Sensor pairing: Add a sensor by scanning a QR code, or by typing a pairing code on devices without a camera; every new sensor waits for an admin's approval.
